# Codex Problems Resolver

Частный репозиторий для воспроизводимых разборов, исправлений, тестов и предупредительных мер по сбоям Codex. Здесь фиксируются доказательства, решения и правила восстановления так, чтобы каждое изменение проходило через Git и было проверяемым.

## Текущее состояние

Репозиторий содержит правила, навигацию, шаблоны задач и запросов на слияние, базовые правила безопасности и точные интерфейсы команд проверки на Python 3 со стандартной библиотекой, добавляемые в рамках текущей начальной настройки.

Это GitOps-governed репозиторий, а не имитация системы выкладки. Git управляет задачами, доказательствами, изменениями, проверками, слиянием и сверкой состояния. Будущая сверка с внешней целевой средой возможна только после появления конкретного управляемого объекта.

## Навигация

- `AGENTS.md` — рабочие правила репозитория для людей и Codex.
- `docs/GITOPS.md` — жизненный цикл инцидента, правила веток, проверок, отката и аварийных исключений.
- `SECURITY.md` — сообщение о уязвимостях, редактура журналов и запрет на секреты.
- `.github/ISSUE_TEMPLATE/incident.yml` — форма регистрации инцидента.
- `.github/pull_request_template.md` — обязательные поля запроса на слияние.

## Планируемые каталоги

- `docs/incidents/` — разборы инцидентов в формате `YYYY-MM-DD-<slug>.md`.
- `docs/runbooks/` — воспроизводимые инструкции диагностики, восстановления и проверки.
- `scripts/` — команды управления на Python 3 и стандартной библиотеке; точные интерфейсы добавляются в рамках текущей начальной настройки.
- `tests/` — автоматические проверки команд, шаблонов и правил.

## Локальные проверки

Точные интерфейсы команд репозитория на Python 3 без внешних зависимостей добавляются в рамках текущей начальной настройки:

```sh
python3 scripts/validate_repository.py
python3 scripts/repository_policy.py validate
python3 scripts/repository_policy.py check --repo RussianLioN/codex-problems-resolver
python3 -m unittest discover -s tests -p 'test_*.py'
```

После появления этих файлов они являются обязательными командами проверки для запросов на слияние. Для проверки пробелов и форматных ошибок в изменениях также используйте:

```sh
git diff --check
```

Изменяющая команда применения политики не является обычной безопасной проверкой и должна запускаться только явно, с подтверждением:

```sh
python3 scripts/repository_policy.py apply --repo RussianLioN/codex-problems-resolver --confirm RussianLioN/codex-problems-resolver
```

Перед запросом на слияние проверьте, что документация соответствует текущим интерфейсам, не содержит секретов и не называет несуществующую систему выкладки.

## Правила изменений

Создавайте задачи для инцидентов, сохраняйте доказательства, работайте в ветках `fix/<issue>-<slug>`, добавляйте проверки, открывайте запросы на слияние и выполняйте откат только через отдельный запрос на слияние. Исключение для начальной настройки разрешено только для ветки `chore/gitops-bootstrap` и должно быть явно описано в запросе на слияние.
