# Восстановление Shift + стрелок для вопросов Codex

## Когда применять

В Codex Shift + ← вместо ожидающего вопроса открывает обзор агентов, а iTerm2
явно отправляет `[D` и `[C` для Shift + стрелок. Разбор и первичные источники:
[инцидент 2026-10-25](../incidents/2026-10-25-plan-question-agent-picker.md).

Команда рассчитана на согласованные пять сохранённых профилей. При другом
количестве, отсутствующих назначениях или неожиданном содержимом она должна
остановиться до записи. Не обходить эту проверку увеличением охвата вслепую.

## Предусловия

- iTerm2 запущен, его интерфейс Python включён; команда выполняется из сеанса iTerm2.
- Известны два неверных назначения и согласован охват всех пяти профилей.
- Во время применения никто не редактирует карты клавиш.
- Доступна текущая рабочая копия репозитория и Python 3.
- Резервная копия находится вне Git; каталог имеет права `0700`, файлы — `0600`.

Полные карты могут содержать чувствительный текст. Не печатать их, не
прикладывать резервную копию к задаче и не добавлять её в репозиторий.

## Подготовка

Из корня рабочей копии создать временное окружение. Зависимости устанавливаются
только в него; обычные проверки репозитория используют стандартную библиотеку.

```sh
ITERM_REPAIR_ENV=$(mktemp -d /private/tmp/iterm-shift-repair.XXXXXX)
python3 -m venv "$ITERM_REPAIR_ENV/venv"
"$ITERM_REPAIR_ENV/venv/bin/python" -m pip install 'iterm2==2.30'
ITERM_REPAIR_STATE="$HOME/.local/state/codex-incidents/2026-10-25-iterm-shift-arrows"
```

Для отдельного будущего применения выбрать новый каталог состояния. Существующий
снимок не перезаписывается. Не сохранять cookie или ключи автоматизации в файлы
или переменные оболочки вручную: авторизацию выполняет библиотека iTerm2.

```sh
python3 -m unittest discover -s tests -p 'test_iterm_shift_arrows*.py'
"$ITERM_REPAIR_ENV/venv/bin/python" ops/iterm2/repair_shift_arrows.py snapshot --state-dir "$ITERM_REPAIR_STATE"
```

Ожидается `snapshot_saved`, пять профилей и число связанных открытых сеансов.
Снимок содержит исходные и ожидаемые карты, но вывод команды — только счётчики.
При системном запросе разрешения автоматизации решение принимает пользователь.
Если окна нет, проверить подключение; не считать ожидание доказательством того,
что пользователь не дал разрешение.

## Применение и независимая сверка

```sh
"$ITERM_REPAIR_ENV/venv/bin/python" ops/iterm2/repair_shift_arrows.py apply --state-dir "$ITERM_REPAIR_STATE"
"$ITERM_REPAIR_ENV/venv/bin/python" ops/iterm2/repair_shift_arrows.py verify --state-dir "$ITERM_REPAIR_STATE"
```

Ожидаются `applied` и `verified`. Повторное применение полностью совпадающего
результата возвращает `already_applied`. Несогласованное промежуточное состояние
требует разбора; не создавать новый снимок поверх неудачной операции.

Операция сохраняет `Action = 10` и изменяет только:

| Ключ | Было | Стало | Байты с Escape |
| --- | --- | --- | --- |
| `0xf702-0x220000` | `[D` | `[1;2D` | `1b 5b 31 3b 32 44` |
| `0xf703-0x220000` | `[C` | `[1;2C` | `1b 5b 31 3b 32 43` |

После применения отдельно прочитать сохранённые настройки iTerm2 и сопоставить
карты с ожидаемыми из закрытого снимка, выводя только число совпадений и число
посторонних изменений. Проверить новую вкладку: она должна получить исправленные
назначения из сохранённого профиля.

## Физическая проверка

Проверка словаря или программная отправка Escape-последовательности не доказывает
работу физической клавиатуры. В отдельной диагностической вкладке получить байты
от реального нажатия Shift + ←, затем Shift + →, и сравнить с таблицей. Режим
терминала после проверки обязательно восстановить.

Затем проверить исходный сценарий в режиме планирования Codex (`/plan`).
Синхронная карточка `request_user_input` может открыться сразу: это подтверждает
отображение, но не работу Shift + ←. Для проверки сочетания создать настоящий
ожидающий вопрос через `request_user_input_async`. Обычным текстом сообщить
пользователю одно действие — нажать Shift + ← после появления подсказки.
Вопрос должен раскрыться, выбранный ответ — поступить агенту. Дождаться ответа,
не завершая текущий шаг сразу после создания вопроса.

На отдельной карточке проверить возврат через Shift + →; после сворачивания
пользователь может подтвердить результат обычным сообщением. Отдельно отмечать
результаты захвата байтов и функциональной проверки с реальной клавиатурой:
один не выдавать за другой. Проверить обычные стрелки. До пользовательской
проверки не отмечать инцидент исправленным полностью.

Для записи результатов, слияния и закрытия задачи выйти из режима планирования
через Shift + Tab. Сам режим планирования допускает проверку и обсуждение,
но запрещает изменение файлов и внешнего состояния.

Не использовать скрытую карточку вопроса как единственный канал просьбы о помощи
при диагностике именно этой неисправности. Если правильные байты не устраняют
сбой, сохранить наблюдение и продолжить разбор обработки ввода в Codex.

## Откат

```sh
"$ITERM_REPAIR_ENV/venv/bin/python" ops/iterm2/repair_shift_arrows.py rollback --state-dir "$ITERM_REPAIR_STATE"
```

Откат использует снимок и журнал начатых записей. Он возвращает только значения,
которые принадлежат этой операции, сохраняя остальные текущие назначения. При
конфликте поздней правки нужной записи команда отказывается её перезаписывать.
Проверить локальный журнал, затем сопоставить сохранённые и действующие карты.
Не импортировать весь старый файл настроек поверх живого iTerm2.

При SIGINT или SIGTERM команда пытается завершить откат до выхода. Отказ записи
журнала не препятствует восстановлению по имеющимся в памяти данным; невозможность
сохранить результат сообщается отдельно. SIGKILL и выключение компьютера не
позволяют выполнить обработчик: после такого прерывания нужен ручной запуск
`rollback` с сохранённым журналом.

## Завершение

Зафиксировать фактически выполненные проверки и ограничения в разборе инцидента.
Пройти проверки репозитория, рецензию и слияние; сверить основную ветку. Закрыть
задачу только после пользовательской проверки. Локальную резервную копию хранить
до завершения приёмки; её удаление не является частью исправления.
