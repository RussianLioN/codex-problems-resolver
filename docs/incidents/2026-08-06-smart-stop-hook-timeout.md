# Превышение срока Stop-хука умных субагентов

## Дата и симптом

6 августа 2026 года при завершении хода Codex отображал сообщение:

```text
Stop hook (failed)
error: hook timed out after 2s
```

Связанная задача: [#4](https://github.com/RussianLioN/codex-problems-resolver/issues/4).

## Окружение

- macOS на архитектуре arm64;
- Codex CLI 0.146.1;
- подключаемый модуль `codex-smart-subagents` 0.2.0;
- пользовательская неизменяемая активация модуля в `<USER_HOME>/.codex`.

Абсолютные пользовательские пути и идентификаторы активаций в этом документе намеренно не приводятся.

## Воспроизведение

1. Запустить Codex с активным модулем умных субагентов.
2. Выполнить ход, который создаёт долговечное состояние маршрута.
3. Завершить ход и дождаться события `Stop`.
4. При холодной загрузке Python либо медленном чтении состояния наблюдать внешнее прерывание через две секунды.

## Доказательства и первопричина

Внешний предел выполнялся раньше, чем тяжёлый обработчик успевал завершить импорты, чтение входа, проверку закреплённой активации и загрузку состояния возобновления. Часть работы происходила до внутреннего отсчёта времени. Поэтому локальные ограничения отдельных операций не гарантировали ответ внешнему процессу Codex.

Дополнительный риск заключался в том, что завершение только непосредственного рабочего процесса могло оставить его дочерний процесс живым. Это расходовало процессы и файловые дескрипторы после уже выданного ответа об ошибке.

## Исправление

Исправление подготовлено в репозитории `RussianLioN/codex-settings`, прошло рецензию в [запросе на слияние #4](https://github.com/RussianLioN/codex-settings/pull/4) и объединено коммитом `61e5eca8cbf2e9dc3fc00505ac4e010d18d62ccf` в ветку `codex/implement-adaptive-subagents-v2`, где расположен исправляемый подключаемый модуль. В ветку по умолчанию `main` этот модуль и исправление пока не входят; брать исходники для установки необходимо по указанной ветке и точному коммиту.

- Лёгкий запускатель начинает единый абсолютный срок до загрузки `site`, сторонних модулей и основного обработчика.
- Рабочий процесс выполняется под родительским надзором; при исчерпании срока завершается его отдельная группа процессов.
- Начальная и повторная проверки закреплённой активации, загрузка состояния и итоговый ответ используют один срок.
- При восстанавливаемой ошибке либо исчерпании срока возвращается один корректный JSON с кодом `SMART_HOOK_DEFERRED` и кодом процесса 0.
- Незавершённое состояние не объявляется завершённым и может быть обработано на следующем ходе.
- Штатный материализатор сохраняет изолированный запуск Python с ключом `-S`, поэтому пользовательский `sitecustomize` не может задержать родительский надзор.

Кэш подключаемого модуля вручную не изменяется. Установка выполняется только штатным атомарным установщиком с предыдущей активацией для отката.

## Проверки

Перед слиянием выполнены следующие проверки исходников:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest tests.smart_subagents.test_plugin_integration tests.smart_subagents.test_integration_runtime_v2 tests.smart_subagents.test_resume_session_v2
git diff --check
```

Результат: 93 интеграционные проверки прошли; шесть целевых проверок единого срока, повторной проверки активации и очистки группы процессов также прошли. Отдельный полный набор материализатора, установки и обновления выполнил 131 проверку без ошибок в закреплённом окружении `uv --locked`.

После слияния в целевую ветку штатный установщик применён к живому пользовательскому профилю из точного коммита `61e5eca8cbf2e9dc3fc00505ac4e010d18d62ccf`:

```sh
python3 scripts/install_adaptive_subagents.py --apply --json
python3 scripts/install_adaptive_subagents.py --apply --json
python3 scripts/install_adaptive_subagents.py --doctor --json
```

Первый запуск опубликовал новую активацию со статусом `FULL_READY` и исходным отпечатком `67201c78ff9cf407b3295d719742dc9e5e7d006bedae9355a46debc3d96f27cf`. Повторный запуск вернул `unchanged`, диагностика — `READY` и тот же отпечаток. Сравнение установленного дерева с объединённым исходником не выявило расхождений; ожидаемо отличается только первая строка запускаемого файла, где материализатор закрепил абсолютный путь изолированного Python.

Чёрноящичная проверка именно установленного запускаемого файла подтвердила два сценария: искусственно задержанный импорт возвращает `SMART_HOOK_DEFERRED` до внешнего срока, а созданный рабочим процессом дочерний процесс отсутствует после ответа. Десять последовательных обычных запусков завершились кодом 0: медиана составила 710,3 мс, максимум — 795,4 мс. В живом `hooks.json` внешний срок `Stop` равен пяти секундам.

## Риски

- Надзор использует возможности POSIX `fork`, отдельную группу процессов и сигналы только собственному рабочему дереву; исправление рассчитано на заявленную macOS-среду.
- Ответ `SMART_HOOK_DEFERRED` переносит незавершённую проверку на следующий ход, поэтому это безопасное продолжение, а не доказательство завершения всей работы.
- Уже запущенный сеанс может продолжать использовать прежнюю активацию до нового запуска Codex.

## Откат

1. Не редактировать неизменяемое дерево активации и кэш вручную.
2. Выполнить предварительный режим отката штатного `scripts/install_adaptive_subagents.py`.
3. Применить откат к предыдущей подтверждённой активации.
4. Выполнить `--inspect`, `--doctor` и чёрноящичную проверку Stop.
5. Если требуется отмена исходников, создать отдельный revert-запрос в `codex-settings`.
