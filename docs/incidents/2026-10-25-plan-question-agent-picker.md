# Shift + стрелка открывает список агентов вместо вопроса

- Дата: 2026-10-25.
- Задача: [#12](https://github.com/RussianLioN/codex-problems-resolver/issues/12).
- Запрос на слияние: [#13](https://github.com/RussianLioN/codex-problems-resolver/pull/13).
- Состояние: исправлено; пользовательская приёмка пройдена 2026-10-26.

## Симптом и окружение

На MacBook Air при ожидающем вопросе Codex сочетание Shift + ← открывает список
агентов. Пользователь сообщает, что на MacBook Pro такого поведения нет.

Проверенное окружение Air: macOS 26.5.2, arm64, Codex CLI 0.164.0 из Homebrew,
iTerm2 3.7.2, профиль по умолчанию. Текущий интерфейс Codex связан с локальным
фоновым процессом той же версии. Настройки Pro не проверены: подключение по
сохранённому адресу не установилось.

## Воспроизведение и доказательства

1. В Codex появляется ожидающий асинхронный вопрос с подсказкой Shift + ←.
2. Поле ввода остаётся пустым.
3. Пользователь нажимает Shift + ← и видит обзор агентов.

Чтение настроек iTerm2 с диска, через `defaults` и через официальный интерфейс
автоматизации дало одинаковые исходные назначения во всех пяти профилях:

| Сочетание | Ключ настройки | Действие | Исходный текст |
| --- | --- | --- | --- |
| Shift + ← | `0xf702-0x220000` | `10` | `[D` |
| Shift + → | `0xf703-0x220000` | `10` | `[C` |

Через интерфейс iTerm2 обнаружены девять открытых сеансов. Их карты клавиш
совпадали с картами соответствующих сохранённых профилей; текущий сеанс найден.
Полные карты, идентификаторы и адреса подключений сохранены только локально.

## Первопричина

В iTerm2 действие `10` отправляет Escape-последовательность. При данных
назначениях Shift + ← превращается в `ESC [ D`, то есть обычную стрелку влево.
Сочетание Shift + → аналогично теряет модификатор. Явные назначения выполняются
раньше обычного кодирования клавиши.

Codex 0.164.0 использует Shift + ← для раскрытия асинхронных вопросов. Обычная ←
при пустом поле и подключении к локальному фоновому процессу открывает обзор
агентов. Поэтому наблюдаемое поведение соответствует получаемой клавише.

- [Обычная стрелка и обзор агентов](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/tui/src/bottom_pane/chat_composer/agents_navigation.rs#L22).

Материалы в этот сервис не публиковались.

## Исправление

Пользователь выбрал исправление всех пяти профилей. Для двух указанных записей
сохраняется `Action = 10`, а `Text` меняется на `[1;2D` и `[1;2C`. В передаваемых
последовательностях параметр `2` сохраняет Shift.

Чистая логика находится в `scripts/iterm_shift_arrows.py`. Эксплуатационная
команда `ops/iterm2/repair_shift_arrows.py` обращается к официальному интерфейсу
iTerm2 из временного окружения. Сначала она сохраняет закрытый снимок вне Git,
затем проверяет исходное состояние и меняет только карты клавиш выбранных
профилей и связанных сеансов. Сессионные карты обрабатываются отдельно.

Повторяемые команды и порядок проверки приведены в
[инструкции](../runbooks/plan-question-agent-picker.md).

тестовые операции в её индекс. Обнаруженные тестовые записи индекса удалены;
рабочие файлы политики не менялись. Временная независимая копия устранила этот
побочный эффект проверки без изменения существующих тестов.

## Риски и откат

Все пять профилей, включая профили удалённых подключений, будут передавать
Shift + стрелки корректно. Программы, которые раньше получали от этих сочетаний
обычные стрелки, могут реагировать иначе; охват согласован пользователем.

Интерфейс iTerm2 не предоставляет условную запись с проверкой версии. Проверки
непосредственно до и после записи уменьшают риск параллельной правки, но не
делают операцию атомарной. Во время применения не редактировать назначения
клавиш вручную.

При сбое применяется точечный откат по локальному журналу. Изменённые позднее
посторонние значения не перезаписываются. Возврат коммита с документацией сам
по себе не восстанавливает настройки iTerm2; сначала выполнить команду отката
из инструкции и проверить результат, затем оформить отдельный запрос на
слияние для изменения материалов инцидента.

Закрытие задачи допускается после физической проверки, подтверждения работы
вопроса, слияния и итоговой сверки основной ветки.
