# HTTP 403 при запуске promo MCP в Codex CLI

Дата разбора: 31 октября 2026 года; исходные ошибки наблюдались 30 октября UTC.

Задача: [#16](https://github.com/RussianLioN/codex-problems-resolver/issues/16).
Запрос на слияние: [#17](https://github.com/RussianLioN/codex-problems-resolver/pull/17).

Статус: promo работает; новый обычный запуск CLI и безопасный вызов проверены.
Настройки не менялись, точная причина первоначальной проверки Cloudflare
не установлена.

## Симптом и окружение

При обычном запуске Codex CLI появляется `MCP startup incomplete` с отказом
`openai-api-credit-promo`: запрос `initialize` получает HTTP 403 и HTML
`Enable JavaScript and cookies to continue` вместо ответа MCP.

Окружение: macOS, Codex CLI и работающий app-server версии 0.166.0,
OpenAI Developers 1.3.13. Плагин `openai-developers@openai-curated-remote`
установлен и включён. Его `.mcp.json` объявляет сервер promo с `auth=chatgpt`
и адресом `https://chatgpt.com/backend-api/product-account-links/mcp`.
Отдельной записи promo в пользовательском `config.toml` нет.

Команда `codex mcp get openai-api-credit-promo --json` возвращает
`No MCP server named 'openai-api-credit-promo' found`. В этом окружении это
не доказывает отсутствие сервера: он поставляется удалённым плагином.

## Воспроизведение и доказательства

Исходный сценарий: запустить `codex` в терминале, дождаться инициализации MCP
и увидеть ошибку promo. Начальная последовательность, гарантированно вызывающая
блокировку в чистом сеансе, не установлена.

| Проверка | Наблюдение |
| --- | --- |
| Журнал работающего daemon | 30 октября, 20:58:01 UTC: отказ инициализации promo, HTTP 403 и HTML Cloudflare |
| Запросы без авторизации через Python и системный curl | HTTP 403, `content-type: text/html`, `cf-mitigated: challenge`; это результат только этих запросов |
| Свежий штатный `codex plugin list --json` | 30 октября, 23:33:47 UTC: успешный `initialize`, сервер `product-account-links` 1.0.0, протокол `2025-06-18` |
| Подключение проблемного разговора | Адресный `mcpServerStatus/list` вернул `authStatus=bearerToken` и три инструмента promo |
| Полезная функция в том же разговоре | Один `preview_api_credit_promo({})` успешен, `isError=false`, без HTTP 403 и HTML challenge |

Проверены инструменты `preview_api_credit_promo`, `discover_api_orgs`,
`link_api_org`. Вызывался только preview. Его дескриптор содержит
`readOnlyHint=true`, `destructiveHint=false`, `idempotentHint=true`,
`openWorldHint=false`; описание исключает привязку организации, активацию
предложения и выдачу кредитов. Значения бонуса, сведения об организациях
и персональные данные в доказательства не включены.

## Разбор причины

Подтверждён механизм исходного отказа: на этапе HTTP сервер вернул проверку
Cloudflare, несовместимую с ожидаемым обменом MCP. Заголовок `cf-mitigated:
challenge` служит документированным признаком такой страницы.
[Распознавание ответа Cloudflare](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/).

Точное правило, вызвавшее проверку, неизвестно. Не доказаны неисправность
учётных данных, влияние VPN, блокировка региона или дефект конкретной версии
CLI. Успешное авторизованное подключение показывает, почему отдельный запрос
без авторизации нельзя использовать как критерий работоспособности promo.

В старых журналах разговоров сервер исключался из каталога из-за отсутствия
готового клиента. Временная блокировка и сохранённое состояние неудачного
подключения остаются возможными объяснениями. При адресной проверке проблемный
разговор уже получил работающий инструмент. Изменение настроек, явное
обновление MCP и повторная авторизация до этого не выполнялись; приписывать
восстановление такому исправлению нельзя.

## Решение консилиума

Проведены три волны с семью отдельными экспертными ролями:

- Волна 1: MCP — проверить штатное авторизованное подключение; SRE — отличить
  HTTP challenge от DNS/TLS-сбоя; безопасность — исключить перенос cookie
  и необоснованную смену авторизации.
- Волна 2: архитектура — сопоставить старый разговор и свежий клиент;
  DevOps — не перезапускать общий daemon без необходимости; приёмка — проверить
  полезный вызов и обычный терминальный запуск отдельно.
- Волна 3: GitOps — закрывать инцидент после проверки исходного сценария,
  ревью и сверки основной ветки.

| Вариант | Решение и ограничение |
| --- | --- |
| Адресная проверка текущего подключения | Первый шаг; сама по себе не заменяет новый запуск CLI |
| Один штатный `config/mcpServer/reload` | Только при подтверждённом устаревшем отказе; затрагивает MCP загруженных разговоров |
| Новый обычный запуск CLI | Проверяет исходный пользовательский сценарий |
| Обновление CLI или плагина | Не требуется без доказанного дефекта версии и применимого исправления |
| Повторный вход | Не требуется: HTML 403 не доказывает неисправность авторизации |
| Обращение в OpenAI | При повторном авторизованном challenge; подготовить обезличенные доказательства |

Отключение promo исключено прямым выбором владельца.

## Повторяемая диагностика и восстановление

1. Проверить `codex --version`, `codex app-server daemon version` и сведения
   о конкретном плагине через `codex plugin list --json`; не публиковать
   полный пользовательский `config.toml` или журналы.
2. В проблемном клиенте открыть `/mcp`. Для программной проверки выбрать
   идентификатор именно этого загруженного разговора, а не последний разговор
   другого клиента.
3. Через существующий app-server выполнить `mcpServerStatus/list` с
   `threadId=<THREAD_ID>`, `serverName=openai-api-credit-promo`,
   `detail=toolsAndAuthOnly`. Подтвердить три инструмента и выполнить один
   безопасный preview. Отсутствие права на бонус является допустимым
   бизнес-ответом и не означает неисправность соединения.
4. Если подключение уже работает, не менять конфигурацию. Если доказано
   устаревшее неудачное подключение при работающем свежем клиенте, после
   завершения активных MCP-вызовов один раз вызвать `config/mcpServer/reload`
   с пустыми параметрами. Команда ставит обновление загруженных разговоров
   в очередь; это не адресное обновление одного сервера. Дождаться изменения
   состояния нужного разговора и повторить только его status и preview.
5. Проверить один обычный новый запуск `codex`. При повторном авторизованном
   HTTP 403 прекратить повторы, оставить инцидент открытым и подготовить пакет
   для поддержки: версии, время UTC, метод и путь без query, код HTTP,
   тип содержимого и признак challenge. Отправка обращения требует поручения.

Управляющий Unix socket app-server использует WebSocket с HTTP Upgrade.
`codex app-server proxy` передаёт байты и не преобразует обычный JSONL
в WebSocket. После handshake клиент выполняет `initialize` и уведомление
`initialized`. Форма безопасного вызова после получения дескриптора:

```json
{
  "id": 3,
  "method": "mcpServer/tool/call",
  "params": {
    "threadId": "<THREAD_ID>",
    "server": "openai-api-credit-promo",
    "tool": "preview_api_credit_promo",
    "arguments": {}
  }
}
```

Поля проверены по схеме установленной версии 0.166.0, созданной во временном
каталоге командой `codex app-server generate-json-schema --experimental
--out <TEMP_DIR>`. Каталог удалён после диагностики. Смысл методов и транспорта
описан в [документации app-server](https://learn.chatgpt.com/docs/app-server).

## Фактическая приёмка и проверки репозитория

31 октября выполнена отдельная приёмка обычного терминального клиента:

1. Запущена существующая обёртка `codex --no-alt-screen` в отдельном PTY
   с `TERM=xterm-256color`. Флаг меняет только отображение; сервер, профиль
   и конфигурация не подменялись. Запрос к модели не отправлялся.
2. После завершения запуска и появления `Ready` команда `/status` позволила
   однозначно сопоставить этот клиент с его новым разговором.
3. Команда `/mcp` в том же клиенте показала
   `openai-api-credit-promo: connected (3 tools)`. Ошибки promo и сообщения
   `MCP startup incomplete` в новом запуске не появлялись.
4. В 14:36:24–14:36:25 UTC адресный status нового разговора вернул три
   инструмента и `authStatus=bearerToken`; один preview вернул нормальный
   структурированный ответ с `isError=false`, без HTTP 403 и HTML challenge.
5. Тестовый клиент штатно закрыт через `/exit`. Общий daemon и чужие клиенты
   не перезапускались. Восстановление подтверждено без изменения настроек
   и без явного `config/mcpServer/reload`.

Предварительные попытки автоматизации не использованы как доказательство
приёмки: `TERM=dumb` останавливал клиент на предупреждении; ошибочный фильтр
OSC скрывал экран; отправка текста и Enter одним быстрым пакетом могла
оставить перевод строки в поле ввода. Итоговая проверка выполнена через
штатный PTY с непосредственным чтением экрана и отдельной отправкой Enter
после ввода slash-команды. Эти ошибки стенда не являются причиной исходного
HTTP 403. Временные диагностические материалы удалены.

Локальные проверки выполнены 31 октября 2026 года:

- `python3 scripts/validate_repository.py` — успешно.
- `python3 scripts/repository_policy.py validate` — успешно.
- `python3 -m unittest discover -s tests -p 'test_*.py'` — 113 тестов, успешно.
- `git diff --cached --check` — успешно.

Новый файл включён в индекс до запуска проверки репозитория. Отдельное
независимое ревью документации не выявило блокирующих замечаний. Новые тесты
не добавлялись: код и установленная конфигурация не меняются. Проверка
удалённой политики выполняется штатным CI после слияния: `full` при наличии
узкого `POLICY_AUDIT_TOKEN`, иначе `builtin` со штатным `github.token` и явными
ограничениями `NOTICE`. Широкий пользовательский OAuth-токен для неё
не используется; политика не применяется.

## Риски и откат

Настройки Codex, плагин, авторизация и сеть не изменялись. Получение кредитов,
`link_api_org`, создание ключей и перенос браузерных cookie не выполнялись.
Первоначальная причина решения Cloudflare остаётся неизвестной; успешное
повторное подключение не гарантирует, что блокировка никогда не повторится.

Изменение репозитория содержит документацию. Файлового отката в установленном
Codex нет; документация отменяется отдельным revert-коммитом через PR.
Не сохранять полный HTML challenge, токены, cookie, частные идентификаторы
разговоров, персональные пути и сырые журналы.
