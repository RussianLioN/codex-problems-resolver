# Инцидент 2026-08-17: мягкий предел открытых файлов в Codex

## Краткий симптом

Активная сессия Codex получила мягкий предел 256 открытых файлов и использовала около 246 дескрипторов. Из-за малого запаса стали возможны сбои при работе с большим числом файлов и подключённых инструментов.

## Окружение и воспроизведение

- Codex CLI в обычной интерактивной сессии на macOS.
- Запустить `codex` в терминале с мягким пределом открытых файлов 256.
- Проверить предел в диагностическом режиме:

```sh
zsh -ic 'ulimit -n 256; eval "alias codex; codex --self-test"'
```

Команда не открывает обычную рабочую сессию Codex; она проверяет развёртывание команды и пределы запуска.

## Обезличенные доказательства

Сессия получила `soft_limit=256` и имела около 246 открытых файлов. Это оставляло около десяти дескрипторов до достижения мягкого предела.

## Первопричина

Обычный интерактивный запуск не поднимал мягкий предел открытых файлов перед передачей управления существующей обёртке `$HOME/.local/bin/codex-highfd`. Жёсткий предел уже был `unlimited`.

## Исправление

Перед редактированием создайте резервную копию `$HOME/.zshrc` без перезаписи существующих копий:

```zsh
(
  backup_path="$HOME/.zshrc.codex-highfd-backup-$(date +%Y%m%d-%H%M%S)"
  [ ! -e "$backup_path" ] || { print -u2 "Резервная копия уже существует: $backup_path"; exit 1; }
  cp -p "$HOME/.zshrc" "$backup_path"
)
```

Найдите в `$HOME/.zshrc` точную существующую строку подключения:

```sh
test -e "${HOME}/.codex/codex-autonomous-aliases.zsh" && source "${HOME}/.codex/codex-autonomous-aliases.zsh"
```

Сразу после неё добавьте ровно одну новую строку:

```zsh
alias codex='ulimit -n unlimited; CODEX_SMART_ENABLED=1 "${HOME}/.local/bin/codex-highfd"'
```

Не изменяются `launchctl`, перехватчики, `$HOME/.codex/config.toml`, квитанция установки и активные процессы. Уже запущенный процесс не изменится; после настройки нужен новый терминал.

## Проверки

Выполнена проверка репозитория:

```sh
python3 scripts/validate_repository.py
git diff --check
```

После настройки ожидаются `soft_limit=unlimited` и `hard_limit=unlimited` в выводе самопроверки; исходное состояние имело `soft_limit=256`, а жёсткий предел уже был `unlimited`.

## Риски и откат

Предел `unlimited` снимает ограничение оболочки, но не отменяет защитные ограничения ядра или отдельного процесса. При необходимости отката удалите только указанную строку из `$HOME/.zshrc` и откройте новый терминал.
