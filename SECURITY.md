# Политика безопасности

## Сообщение о уязвимостях

Сообщайте о уязвимостях через private GitHub security advisory в этом репозитории. Не создавайте публичные задачи с рабочими секретами, эксплойтами, токенами, приватными ключами, cookie или необезличенными журналами.

В сообщении укажите:

- краткое описание риска;
- затронутые файлы, команды или сценарии;
- воспроизведение с обезличенными данными;
- ожидаемое безопасное поведение;
- уже выполненные меры сдерживания, если они были.

## Редактура журналов и доказательств

Перед добавлением журналов, снимков состояния или выдержек команд удаляйте или заменяйте:

- токены, ключи, пароли, cookie и одноразовые коды;
- приватные ключи и секретные фразы;
- значения заголовков `Authorization` и аналогичных полей;
- личные адреса, номера телефонов и идентификаторы пользователей, если они не нужны для воспроизведения;
- абсолютные пути к домашнему каталогу и имена локальных машин;
- сетевые адреса и имена частных узлов, если они не являются обязательным доказательством.

Используйте стабильные маркеры:

```text
<REDACTED_TOKEN>
<REDACTED_PASSWORD>
<REDACTED_COOKIE>
<USER_HOME>
<PRIVATE_HOST>
```

## Запрещённые материалы

В репозиторий нельзя добавлять рабочие секреты, `.env` с реальными значениями, дампы сессий, приватные ключи, полные журналы авторизации и необезличенные выгрузки пользовательских данных.

Если для диагностики нужен пример, создайте минимальный обезличенный фрагмент, достаточный для воспроизведения.

## Подозрение на раскрытие секрета

Если есть подозрение, что секрет был раскрыт:

1. Немедленно ротируйте затронутый токен, пароль или ключ.
2. Отзовите активные сессии, если это применимо.
3. Создайте private GitHub security advisory.
4. Зафиксируйте, где секрет мог быть раскрыт и какие действия выполнены.
5. Проверьте историю Git и открытые запросы на слияние на наличие того же значения.
6. Добавьте или усилите проверку редакции, чтобы предотвратить повторение.
